# LINKO 1.1.0-preview.1

휴대폰 앱 없이 화면 가장자리에서 입력을 전환하는 실험 기능과 Windows 입력·Bluetooth 복구 분리를 포함한 테스트 버전이에요. 휴대폰을 Windows 확장 디스플레이로 등록하거나 PC 화면을 전송하는 기능은 아니에요. 휴대폰 자체 화면을 PC 키보드와 마우스로 조작해요.

**실제 Android·iPhone은 연결되지 않아 장시간 사용, 끊김, 다른 휴대폰 앱의 화면 새로고침 현상은 아직 검증하지 못했어요.** 아래 자동 검사 통과를 실제 증상이 해결됐다는 뜻으로 보지 말아 주세요. 정식 최신 버전은 1.0.15를 유지해요.

트레이의 기존 LINKO를 **종료**하고 새 EXE를 실행해 주세요. 창의 X는 트레이로 숨기는 동작이에요. 기존 페어링과 설정을 유지하며, 기기를 선택하고 **이 기기 사용**을 누르면 돼요. Android와 iPhone 모두 키보드·마우스 및 가장자리 전환에 휴대폰 앱이 필요하지 않아요. iPhone은 기존 연결 안내대로 AssistiveTouch를 켜 주세요.

Android APK는 클립보드 동기화용이에요. 이 버전은 Windows와 버전만 맞췄고 Android 동작 변경은 없어요. Android LINKO를 사용한다면 1.0.15까지의 수정이 적용되도록 APK도 업데이트해 주세요. EXE만 교체하면 Android 앱 코드는 바뀌지 않아요.

## 자동 전환 켜기

1. 휴대폰 연결 후 **입력 설정**에서 **휴대폰 위치**를 오른쪽 또는 왼쪽으로 선택해요. 기본은 오른쪽이고 자동 전환은 처음엔 꺼져 있어요.
2. **이동 범위 보정**을 눌러요. 키나 마우스 버튼을 누르고 있다면 먼저 놓아 주세요.
3. 휴대폰 커서를 PC에 가까운 쪽 끝에 놓고 **F8**을 눌러요. 휴대폰이 오른쪽이면 왼쪽 끝, 왼쪽이면 오른쪽 끝이에요.
4. 평소 속도로 반대쪽 끝까지 이동한 뒤 **F8**을 눌러요.
5. 비슷한 속도로 처음 끝으로 돌아와 **F8**을 누르면 보정값을 저장하고 자동 전환을 켜요. 보정 중 **F9**는 취소예요. 단축키를 바꿨다면 화면에 표시된 키를 사용해 주세요.
6. PC 커서를 선택한 쪽의 가장 바깥 화면 끝으로 밀면 휴대폰 조작으로 전환해요. 휴대폰에서 PC 쪽으로 움직여 추정 경계를 넘으면 PC로 돌아와요.

보정값은 기기마다 저장해요. 정상 왕복 이동량의 평균을 사용하며, 양쪽 이동량 차이가 35%를 넘으면 다시 보정하도록 안내해요. 표시되는 이동 범위는 전송한 마우스 이동량 기준이며 화면 픽셀 수가 아니에요.

## 전환 동작과 한계

- Windows 모니터 사이의 경계에서는 전환하지 않아요. 커서 높이에서 가장 바깥쪽 경계를 사용하며, 음수 좌표와 서로 다른 배율의 모니터 배치를 고려해요.
- 키나 마우스 버튼을 누르는 동안에는 자동 진입·복귀를 하지 않아요. 가장자리에서 키만 놓는 것으로 나중에 전환하지 않도록 다시 안쪽으로 움직여 접근해야 해요.
- 전환 준비 중에는 PC 입력을 유지해요. 휴대폰 입력 해제를 확인하고 커서가 여전히 가장자리에 있는지 확인한 뒤 전환해요. 자동 진입 시 휴대폰 커서를 가까운 쪽 끝으로 이동시켜 추정 위치를 맞춰요.
- PC로 돌아오면 진입했던 모니터와 높이의 가장자리 안쪽 16픽셀에 커서를 놓아요. 모니터가 사라졌다면 현재 화면으로 복귀해요.
- 휴대폰 커서의 실제 좌표를 읽지 않아요. 성공적으로 전송한 상대 이동량으로 추정하므로 휴대폰 가속도·감도·회전·화면 크기 변경에 따라 오차가 생길 수 있어요. 설정을 바꾸면 다시 보정해 주세요. **F8 수동 전환과 F9 즉시 복귀는 계속 사용할 수 있어요.**
- 연결이 끊기거나 Windows가 잠기거나 절전에 들어가면 PC로 복귀해요. 다시 연결돼도 자동으로 휴대폰 입력을 재개하지 않아요.

## 입력과 Bluetooth 안정성 변경

- Windows 입력 훅에서는 Bluetooth 전송, UI 처리, 로그 파일 쓰기를 기다리지 않도록 분리했어요. 다른 처리가 지연되거나 대기열이 넘치면 PC 입력을 다시 통과시켜요.
- 입력 전송 복구 대기를 3초에서 **500ms**로 줄였어요. 취소를 무시하는 비동기 전송도 기다리는 시간을 제한하고, 오래된 대기 입력을 버려요. 전환 세대가 다른 입력·실패·예약 작업이 새 입력 세션에 적용되지 않도록 확인해요. 이는 OS 스케줄링까지 포함한 절대 500ms 응답 보장은 아니에요.
- 확정된 입력 연결 상실은 UI 처리와 별도로 PC 복귀를 시도해요. 입력 해제 보고가 실패하면 로컬 상태에서 현재 기기·세션을 확인해 다시 시도해요.
- 정상 입력 전환마다 훅이나 GATT 서비스를 다시 만들지 않아요. 활성 연결이 있거나 최근 **5초** 안에 상대 활동이 관찰되면 검색 신호 오류에 따른 서비스 재게시를 보류해요. HID와 선택적 클립보드 채널이 이 판단을 공유해요.
- 클립보드를 꺼 두면 재시작 후에도 꺼진 설정을 유지해요. 끄는 순간 기존 Bluetooth 서비스를 재구성하지 않고 전송을 중단해요. 꺼진 상태로 시작하면 선택적 클립보드 서비스를 만들지 않아요.
- 진단 로그를 비동기로 쓰고 벽시계·단조 증가 시각, 버전, 전환·복귀 이유를 남겨요. 입력한 키와 클립보드 본문은 남기지 않아요.

반복적인 연결 상태 변경이 다른 휴대폰 앱의 화면 재생성에 영향을 줄 수 있는 경로를 줄였지만, 사용자가 겪은 다른 앱의 새로고침 원인을 실기기에서 특정한 것은 아니에요.

## 완료한 검사

- Core 검사 **243개 통과**: 경계·방향·누른 키 차단, 다중 모니터 배치, 왕복 보정, 추정 복귀, 전송 제한, 오래된 입력·세대 분리, 복구 대기 경계를 포함해요.
- Windows Release 빌드와 단일 EXE 생성, 소스 정합성 검사 통과. 빌드 경고·오류 0.
- 실제 Windows 입력 스레드에서 처리기를 멈춰도 훅이 빠르게 반환하는 검사, 지연 시 로컬 복귀, 이전 세대 입력 폐기, 보정 F8/F9 검사 통과. OS에 키 입력을 주입하지 않고 훅 호출을 사용했어요.
- 입력 전환 대기, 단축키 범위, 설정 유지, 기기 목록, UI 종료·복구 검사와 실제 Windows 클립보드 왕복 검사 통과. 입력 설정 화면을 렌더링해 확인했어요.
- Windows 네이티브 GATT 복구 검사 통과: 연결 관찰값을 주입한 100회 상태 확인에서 연결 중 재게시 억제, 연결 종료 후 복구, 게시 실패 반복 억제, 선택적 서비스 지연 준비를 확인했어요. **실제 휴대폰 연결 검사가 아니에요.**
- Android JVM 검사 **52개 통과**, 실패·오류 0. APK 빌드 성공.

Android에서는 **LINKO 앱 강제 종료 + PC 클립보드 끄기**와 **Android LINKO 동작 + 클립보드 켜기**를 나눠 비교해 주세요. 앱 화면만 닫아도 백그라운드 서비스가 남아 있을 수 있어요. 문제 발생 시각, 기기/OS, 감도, 앱 동작 여부를 기록하고 PC **도움말 → 진단 파일 저장**을 사용해요. 동반 앱이 실행 중이면 Android 연결 진단 로그도 함께 확인해요.

실기기 확인표를 채우기 전에는 테스트 릴리스로 유지해요. 문제가 있으면 자동 전환을 끄고 F8/F9를 사용하거나, 트레이에서 종료 후 1.0.15 EXE로 돌아갈 수 있어요.
