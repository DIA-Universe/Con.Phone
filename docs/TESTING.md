# 검증표

## 현황

| 항목 | 상태 |
|---|---|
| Core 자동 시험 | GitHub Actions의 해당 커밋 로그로 확인 |
| Windows 컴파일/배포 | GitHub Actions의 해당 커밋 로그로 확인 |
| Windows 실제 UI 실행 | 미검증 |
| 내장 Bluetooth 광고/페어링 | 미검증 |
| 갤럭시 실제 입력 | 미검증: 첫 사용자 시험 대상 |
| iPhone 실제 입력 | 미검증: 테스트 기기 없음 |
| 이지블루 대비 지연/안정성 | 비교하지 않음 |

컴파일 성공만으로 위의 미검증 항목을 통과로 바꾸지 마세요.

## 첫 시험 순서

1. PC 모델, Windows 빌드, 내장 Bluetooth 칩셋/드라이버 버전, 갤럭시 모델/One UI 버전을 수동 기록합니다. 공개 로그에 기기 주소/개인정보를 넣지 않습니다.
2. 앱 검사 결과의 Peripheral=True를 확인합니다. False이면 중단하고 결과를 기록합니다. 동글로 대체하지 않습니다.
3. 광고 상태가 Started인지 확인합니다. StartedWithoutAllAdvertisementData는 완전한 광고 성공과 구분합니다.
4. 휴대폰 설정에서 PC가 보이는지, 양쪽 확인을 거쳐 페어링되는지 확인합니다. 다른 기기는 시험 중 연결하지 않습니다.
5. 키보드/마우스 구독 및 OS 페어링 상태가 모두 True인지 확인합니다. 구독 실패를 입력 버그로 기록하지 않습니다.
6. 본인 기기를 승인한 뒤 F8을 누릅니다. PC 메모장에는 입력되지 않고 휴대폰에만 입력되는지 봅니다. PC 커서가 움직이거나 Raw Input이 전달되지 않으면 F9로 복귀합니다.
7. 영문 → 한글 → 한영 전환 → Backspace/Shift → 클릭 → 드래그 → 휠 순서로 시험합니다.
8. F9, Bluetooth 끄기, 잠금, 절전, 앱 종료, 연결 재개 상황에서 로컬 조작권을 확인합니다. 휴대폰의 키 해제까지 별도로 확인합니다.

## 회귀 시험 목표 (달성치 아님)

| 시나리오 | 목표 |
|---|---|
| F8/F9 전환 | 100회, 잘못된 대상 입력/눌림 잔류 0건 |
| 문자 입력 | 1,000자, 의도하지 않은 누락·중복 0건 |
| 드래그 | 100회, 버튼 눌림 순서 손실 0건 |
| 혼합 입력 | 30분, 무한 대기열/앱 멈춤 없음 |
| 재연결 | 20회, 원격 입력 자동 재개 없음 |
| 추가 기기 연결 | 승인되지 않은 기기에 키 보고서 노출 없음 |

테스트에는 비밀번호, 고객정보, 회사 데이터를 사용하지 않습니다. IME 상태를 프로그램에서 추측하지 않습니다. 언어 전환 키는 휴대폰 설정을 기준으로 확인합니다. 프로그램의 send 완료 횟수는 휴대폰에서 글자가 반영된 횟수가 아닙니다. 종단 지연은 별도 촬영 등으로 측정해야 합니다.
