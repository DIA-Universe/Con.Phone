# LINKO 1.0.14 — Bluetooth 연결 복구와 입력 전환

## 휴대폰에서 ‘노트북에 연결할 수 없음’이 뜨는 경우

기존 LINKO를 PC 트레이의 **종료**로 완전히 닫고 [1.0.14 EXE](https://github.com/DIA-Universe/Con.Phone/releases/download/v1.0.14/LINKO.exe)를 실행하세요. 창의 X는 트레이로 숨기는 동작입니다.

1. 휴대폰 Bluetooth 설정에서 이 PC를 선택해 연결합니다. 이 빌드는 PC에서 상대 기기로 역방향 연결을 요청하지 않습니다.
2. 실패가 반복되면 PC LINKO의 **기기 연결 → 연결 복구 (앱 다시 시작)**를 한 번 누릅니다. 창이 다시 열린 뒤 휴대폰 Bluetooth 설정에서 PC를 다시 선택하세요.
3. Windows LINKO에서 휴대폰을 선택하고 **이 기기 사용**을 누릅니다. Android LINKO의 PC 선택 목록에 PC가 없다면 휴대폰 OS의 페어링 목록부터 확인하세요. Android 앱은 페어링 목록을 사용합니다.

복구 후에도 휴대폰 OS에서 연결을 거절하면, 휴대폰에서 해당 PC와 Windows에서 해당 휴대폰의 페어링만 각각 해제한 뒤 LINKO를 실행한 상태에서 휴대폰이 페어링을 다시 시작하도록 해 보세요. 이때 PIN을 양쪽에서 확인하고 LINKO에서 기기를 다시 선택해야 합니다. EXE가 페어링을 자동 삭제하거나 다른 Bluetooth 장치/드라이버를 초기화하지는 않습니다. 기기 제거 후 재페어링은 [Microsoft 연결 실패 안내](https://support.microsoft.com/en-us/windows/hardware/bluetooth/troubleshoot-bluetooth-not-connecting-in-windows)에도 제시된 복구 단계입니다.

그래도 실패하면 **도움말 → Bluetooth 진단 보기 → Bluetooth 다시 검사**와 **상세 로그 보기 → 진단 파일 저장**으로 당시 상태를 남겨 주세요. 현재 개발 PC에는 문제의 휴대폰 연결을 재현할 수 있는 실기기가 없습니다. 아래 코드 결함을 사용자가 겪은 연결 실패의 원인으로 단정하지 않습니다.

## Bluetooth 변경과 근거

- `EnsureAdvertisingAsync`는 서비스 수명이 이미 취소됐어도 Windows의 광고 상태가 `Started`이면 성공으로 반환했습니다. 서비스가 살아 있는지도 확인하도록 수정했습니다. 취소된 수명과 지연된 `Started` 상태를 주입한 검사에서 수정 전 실패, 수정 후 실제 네이티브 서비스 재생성 및 광고 시작을 확인했습니다.
- 정상 서비스는 그대로 유지합니다. 단순 광고 오류나 HID 구독 대기만으로 자동으로 서비스를 파괴하거나 앱을 재시작하지 않습니다.
- 새 **연결 복구 (앱 다시 시작)**는 사용자가 누른 경우에만 동작합니다. 기존 프로세스가 완전히 끝난 뒤 새 프로세스가 GATT 서비스를 만듭니다. 종료 전에는 새 Bluetooth 서비스를 열지 않습니다. 이전 프로세스의 PID와 생성 시각을 함께 확인하고 최대 30초 대기합니다. 재시작 준비가 실패하면 기존 창을 유지하고, 기존 프로세스가 종료되지 않으면 강제 종료 없이 안내합니다.
- 페어링·신뢰 기기·설정 저장소를 삭제하지 않습니다. 1.0.12/1.0.13의 페어링된 기기 표시와 Bluetooth 연결/HID 준비 상태 구분을 포함합니다. 목록 조회가 세션을 교체/해제하지 않는 동작도 유지합니다.

## 입력 전환 오류

사용자는 전환 단축키와 화면의 전환 버튼 양쪽에서 ‘입력 전환 단축키 외의 키와 마우스
버튼을 모두 놓아 주세요’가 나오며 전환되지 않는다고 보고했습니다.

## 확인한 경로

두 경로는 `ToggleAsync`에서 공통으로 `InputCapture.Activate`를 호출합니다.
이때 `GetAsyncKeyState`의 최상위 비트로 현재 키/마우스 눌림을 검사하고, 설정된 전환
단축키 이외의 입력이 하나라도 있으면 즉시 예외를 발생시켰습니다. 키를 뗄 시간을 기다리지
않고, 어떤 입력이 막았는지 메시지에 넣지도 않았습니다. 메시지의 발생 지점은 이 로컬
전환 검사이며 Bluetooth 연결 오류 메시지가 아닙니다.

사용자의 실제 차단 키는 기존 로그에 없으므로 아직 특정하지 못했습니다. 물리적으로
눌린 키/버튼인지, Windows에 남은 눌림 상태인지도 확정하지 않습니다.

## 변경

- 키와 마우스 버튼을 놓을 시간을 최대 2초 기다리며 25ms마다 다시 확인합니다.
  기다리는 동안 입력은 계속 PC에서 처리하며 UI/입력 훅 스레드를 잠재우지 않습니다.
- 키가 풀리면 같은 요청에서 전환을 이어갑니다. 대기 중 연결/대상/입력 세대가 바뀌거나
  종료가 시작되면 활성화하지 않습니다. 실제 눌림 상태를 강제로 지우거나 key-up을 주입하지 않습니다.
- 2초 후에도 막히면 ‘Windows가 눌림으로 감지한 입력: 왼쪽 Ctrl’처럼 입력 이름을
  표시합니다. 좌우 구분, 마우스 추가 버튼, 한/영·한자 키를 포함합니다. 일반 Ctrl 코드와
  왼쪽 Ctrl처럼 같은 상태를 가리키는 별칭은 중복 표시하지 않습니다.
- 대기 안내와 최종 차단 사유는 화면 피드백과 로그에 남습니다. 차단된 검사는 입력 모드나
  modifier key-up 처리를 부분적으로 바꾸지 않습니다.
- F7로 휴대폰 대상을 바꾼 뒤 입력을 재개하는 경로에도 같은 대기/진단을 사용합니다.
  기존 F9의 로컬 일반 키/원격 복귀 범위는 유지합니다.
- Android 연결 코드는 변경하지 않았습니다. APK의 표시 버전만 1.0.14로 맞췄습니다.

## 검증

- Windows Release 빌드 경고/오류 0개.
- 제품 활성화 함수 검사 11개: Ctrl 차단과 이름, 별칭, 마우스 해제 후 전환,
  modifier 해제 후 전환, 사용자 Ctrl+F8 허용, 대기 중 연결/대상 취소, 종료 취소,
  계속 누른 추가 버튼의 제한 시간, `GetAsyncKeyState` 하위 비트만 켜진 경우를 검사합니다.
- 위 검사는 실제 제품의 입력 활성화 함수에 제어된 키 상태 읽기를 주입합니다. OS에 키를
  주입하지 않으며 사용자 기기의 ‘눌림 상태 잔류’를 재현한 것으로 표시하지 않습니다.
- 프로세스 종료 대기 6개 검사: 자기 자신/PID 생성 시각 불일치 거절, 시간 초과 시 기존 프로세스 유지, 실제 종료 전후 대기, 이미 종료된 경우를 확인합니다.
- WinForms 종료 검사에 연결 복구를 추가했습니다. 재시작 준비 실패 시 기존 창 유지, 중복 클릭 시 한 번만 요청, 정상 종료 후 숨은 프로세스로 남지 않는지 검사합니다.
- F9 범위/최종 배포 EXE/Android 빌드의 최종 검사 결과는 GitHub 릴리스에 기록합니다.
- 물리 Bluetooth 끊김, 실제 휴대폰의 입력 복구와 마우스 지연은 별도 미검증 상태입니다.

## 입력 전환 경고가 계속될 때

PC 트레이에서 LINKO를 종료한 뒤 1.0.14 EXE로 실행합니다. 이번 수정은 PC에만 적용됩니다.
화면에 특정 키/버튼이 계속 표시되면 해당 입력을 한 번 눌렀다 떼고 다시 전환해 보세요.
그 후에도 표시되면 정확한 키/버튼 이름이 원인 확인에 필요합니다.

API 근거: [GetAsyncKeyState의 눌림 비트와 마우스 버튼 동작](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getasynckeystate).
